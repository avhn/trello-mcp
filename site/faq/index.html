Trello MCP FAQ

Answers about connecting Trello to Claude, Codex and ChatGPT, choosing access policy and understanding token estimates.

What is trello-mcp?

trello-mcp is an independent, MIT-licensed Trello MCP server written in Go. It lets Model Context Protocol clients manage Trello boards, cards, checklists and attachments through a local stdio process, without a hosted intermediary.

Which clients can use this Trello MCP server?

The documented configurations cover Claude Code, Claude Desktop, Codex CLI, Codex desktop, ChatGPT desktop and OpenCode. Other clients can use local stdio transport with their own configuration format. The Codex clients and ChatGPT desktop share ~/.codex/config.toml.

How do I connect my Trello account?

Run trello-mcp auth in a terminal after installation. Create an API key manually at Trello Power-Ups administration when prompted, approve the authorization link and paste the token at the hidden terminal prompt. The command validates and saves credentials. Restart your MCP client afterward. If a release does not recognize auth, build current source or supply both environment credentials.

Are writes enabled by default?

Yes. trello-mcp auth defaults to write access: Enter at Allow write access? [Y/n] means yes. Use trello-mcp auth --read-only to request a read-only token, or TRELLO_READ_ONLY=1 to hide mutation and transfer tools. A saved read-only token cannot be upgraded by setting TRELLO_READ_ONLY=0.

Why does my client only show server_health?

Without configured credentials, the server still initializes but registers only server_health, with an account-setup hint. Run trello-mcp auth outside the MCP transport, then restart your client. A complete TRELLO_API_KEY and TRELLO_TOKEN environment pair overrides saved credentials; a partial pair is an error.

Where are credentials stored?

Credentials use unquoted KEY=VALUE lines in ~/.secrets/.trello-mcp.secret on every platform. The three keys are TRELLO_API_KEY, TRELLO_TOKEN and optional TRELLO_TOKEN_SCOPE; read scope forces read-only. Precedence is the complete environment pair, TRELLO_MCP_CREDENTIALS file, default file, then ~/.secrets.env (the shared avhn/secret store). Auth creates missing Unix folders as 0700 and files as 0600, or protected owner-only Windows DACLs; it never changes existing folder permissions. Unsafe ownership, permissions and symlinks are refused. Using secret is optional.

Does logout revoke my Trello token?

No. trello-mcp auth logout removes only the three Trello keys, preserving unrelated lines and comments and deleting the file only if empty. It never modifies ~/.secrets.env, revokes the Trello token, unsets environment credentials or clears local selections. Shared or environment credentials may still authenticate. Revoke the token through Trello when needed, and restart clients after logout.

Can I restrict access to specific workspaces?

Yes. TRELLO_ALLOWED_WORKSPACES accepts comma-separated workspace ids or canonical names, not display names. Unset means unrestricted within token permissions. The server resolves actual object ownership; supplied board ids cannot bypass the allowlist. Moves and copies check both boards.

Does it discover guest boards?

board_find searches all account boards, including guest boards visible to your token, unless workspaceId narrows the search; the optional allowlist still applies. Atlassian's documentation says its connector accesses only workspaces explicitly authorized on its consent screen. It does not establish whether guest-only boards are accessible, so no guest-board exclusion is claimed here.

Are the token savings live tokenizer measurements?

No. The README table reports estimated tokens using characters / 4 on synthetic fixtures, compared with the raw pretty-printed response style of @delorenj/mcp-server-trello 1.8.1. These are reproducible offline size estimates, not live account measurements or tokenizer counts. The tool-definition row is not a like-for-like measured comparison. Tool-call requests, protocol framing and model-specific tokenization are excluded.

Why is a tool hidden or an operation denied?

Call server_health with detail set to policy before assuming the token is broken. Tool selection, read-only mode, the workspace allowlist and platform transfer checks can refuse operations. Policy errors identify server policy; upstream HTTP 401/403 errors identify a token/permission issue. Keep server or server_health in custom TRELLO_TOOLS profiles.

Can I upload and download attachments on Windows?

Windows refuses local path uploads and attachment downloads because their ownership and path checks require Unix. Base64 uploads and URL attachments remain available when writes are enabled. On supported Unix platforms, path uploads need a dedicated TRELLO_UPLOAD_DIR. Uploads and downloads are capped at 10 MiB; no inline attachment bodies are returned.

Does read-only mode prevent every local change?

No. Read-only mode hides Trello mutations and attachment transfers, including local-file downloads, but workspace_use and board_use can still change local defaults. The server policy does not replace a suitably scoped Trello token.

Is this the official Atlassian Trello MCP connector?

No. trello-mcp is an independent Go implementation. The MIT-licensed @delorenj/mcp-server-trello 1.8.1 is the tool-coverage reference, not a runtime dependency. This project is not the Atlassian-hosted connector.

Credential files and optional secret tooling

MCP configs need only the full binary path. The default credential file is ~/.secrets/.trello-mcp.secret on every platform (%USERPROFILE%\.secrets\.trello-mcp.secret on Windows). Locations and value rules follow avhn/secret, "Let coding agents use your credentials without reading them". The bare name trello-mcp resolves to this file: secret show trello-mcp lists masked names and secret exec -f trello-mcp ... can launch a configured consumer. Using secret is optional; trello-mcp reads files itself.

TRELLO_API_KEY=your-api-key
TRELLO_TOKEN=your-token
TRELLO_TOKEN_SCOPE=read,write

Values follow secret stash: unquoted KEY=VALUE, nonempty, no NUL, CR, embedded newlines, boundary whitespace or surrounding quote pairs; one final LF is allowed. Scope is optional (unknown, treated as writable); read forces read-only even with TRELLO_READ_ONLY=0.

Precedence: environment TRELLO_API_KEY + TRELLO_TOKEN > absolute TRELLO_MCP_CREDENTIALS file > dedicated default file > ~/.secrets.env. Partial environment pairs fail; missing or credential-free files fall through without merging keys across files. The final fallback is secret's shared top-level store; only the three Trello keys are interpreted and unrelated values are ignored, never logged. An unsafe shared file is bypassed when an earlier source exists, otherwise it produces a clear error. Auth never modifies the shared store.

Auth creates missing directories as 0700 and files as 0600 on Unix, or protected owner-only DACLs on Windows. Auth also repairs the default ~/.secrets to 0700 after refusing symlinks and foreign owners, matching secret stash. Reads and logout require no group/world bits (0077) there. Custom parents and the home parent of read-only ~/.secrets.env may be 0755, but not group/world writable (0022); custom modes are unchanged. Symlinked files/parent paths, foreign ownership, group/world-writable Unix directories and group/world-accessible files are refused. Windows verifies owner and protected owner-only DACLs; the shared file's home parent need not have an owner-only DACL. See exact errors and corrective permission instructions.

Save and logout hold the target parent's .write-lock across the entire read-modify-write, including deletion. This mkdir protocol matches secret stash for the default store, with private token/PID files and token-checked release. Reads do not lock. Writers retry every 100ms for up to 3s. Timeout errors name the lock: verify its PID is stopped before manually removing it. Locks are never auto-stolen. Logout rechecks content before deletion and rewrites a changed file instead. Writers ignoring the protocol cannot be serialized.

auth, auth status and auth logout accept --file /absolute/path/account.secret. Set TRELLO_MCP_CREDENTIALS for future client processes; environment credentials still override files. Status validates the username and granted scope, one fact per line without secrets; shared fallback reports Credential source: file ~/.secrets.env (shared store). Logout removes only the three keys, preserves unrelated lines/comments and deletes the file only if empty. It does not revoke tokens or clear environment/shared credentials. Restart clients afterward.

Without the browser flow, privately edit the three lines with an existing key/token and actual scope. On Unix create a missing folder with mkdir -m 700 ~/.secrets, edit after umask 077, then chmod 600 ~/.secrets/.trello-mcp.secret. Ensure an existing ~/.secrets belongs to you and is intended to be private, then run chmod 700 ~/.secrets; auth and secret stash also repair this default. Alternatively secret stash trello-mcp TRELLO_API_KEY (and token/scope equivalents) prompts privately. Windows requires protected owner-only DACLs in Properties > Security. Run trello-mcp auth status to validate.

Troubleshooting: no credentials found means run auth and restart; permission refused means follow the exact storage error and safe fix; 401 means check token expiry/revocation and the matching key; wrong workspace denial means inspect server_health with {"detail":"policy"} and fix server policy rather than changing credentials.
