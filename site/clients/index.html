Local stdio client configuration

Connect your MCP client

Use trello-mcp with Claude Code, Claude Desktop, Codex, ChatGPT desktop, OpenCode or another Model Context Protocol client.

Install trello-mcp and connect your Trello account first. These snippets use saved credentials and leave writes enabled. Replace every placeholder with your full installed executable path. No API key or token belongs in these snippets.

  • Claude Code
  • Claude Desktop
  • Codex and ChatGPT
  • OpenCode
  • Generic MCP JSON
  • Access policy

Claude Code

For the default macOS or Linux installation:

claude mcp add trello --transport stdio -- "$HOME/.local/bin/trello-mcp"

Adjust the path for a Go installation (~/go/bin by default), a custom install directory or Windows. The installers print a registration command using the installed path.

For a default Windows install in PowerShell:

claude mcp add trello --transport stdio -- "$env:LOCALAPPDATA\Programs\trello-mcp\trello-mcp.exe"

Claude Desktop

Merge the following mcpServers object into your local configuration. Do not replace unrelated servers or settings.

{
  "mcpServers": {
    "trello": {
      "command": "/absolute/path/to/trello-mcp"
    }
  }
}
  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json
  • Claude Desktop has no official Linux build.

Desktop apps do not inherit your shell PATH. Use an absolute executable path and restart Claude Desktop after saving.

Windows JSON paths

Use trello-mcp.exe and double backslashes in JSON. Replace YOUR_USER in this default-install example:

{
  "mcpServers": {
    "trello": {
      "command": "C:\\Users\\YOUR_USER\\AppData\\Local\\Programs\\trello-mcp\\trello-mcp.exe"
    }
  }
}

The native installer prints the correct path and escaping for your machine.

Codex CLI, Codex desktop and ChatGPT desktop

The Codex CLI, Codex desktop and the ChatGPT desktop app share ~/.codex/config.toml. Merge this into that local file, then restart the client:

[mcp_servers.trello]
command = "/absolute/path/to/trello-mcp"

In ChatGPT desktop, check Settings, MCP servers. You can also add it there by hand: Add server, type STDIO, then use the same full executable path.

Windows TOML basic strings need doubled backslashes, just like JSON. Replace the user placeholder:

[mcp_servers.trello]
command = "C:\\Users\\YOUR_USER\\AppData\\Local\\Programs\\trello-mcp\\trello-mcp.exe"

OpenCode

Merge a local MCP entry into your OpenCode configuration:

{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "trello": {
      "type": "local",
      "command": ["/absolute/path/to/trello-mcp"],
      "enabled": true
    }
  }
}

OpenCode uses a command array and type: "local", rather than the generic mcpServers format. Use a full path, with JSON escaping on Windows.

Generic MCP JSON

For clients accepting mcpServers:

{
  "mcpServers": {
    "trello": {
      "command": "/absolute/path/to/trello-mcp"
    }
  }
}

Client-specific formats may differ. Select local stdio transport, not an HTTP server URL. Keep credentials out of committed files.

Optional read-only access and workspace policy

Read-only is opt-in. Run trello-mcp auth --read-only, or add TRELLO_READ_ONLY=1 to the server's environment. A saved read-only token cannot be upgraded by setting the variable to 0.

For clients that accept env in an MCP JSON server entry, this example restricts access to the workspace with canonical name team and hides writes:

{
  "mcpServers": {
    "trello": {
      "command": "/absolute/path/to/trello-mcp",
      "env": {
        "TRELLO_READ_ONLY": "1",
        "TRELLO_ALLOWED_WORKSPACES": "team"
      }
    }
  }
}

Replace team with an allowed workspace id or canonical name, not a display name. See the access policy and security guide before enabling transfers.

Only server_health appears?

Without credentials, the server still initializes but registers only server_health. Run trello-mcp auth in a terminal, then restart your client. If tools are hidden or operations are refused after setup, call server_health with {"detail":"policy"} to inspect server policy.

See the tool reference and troubleshooting FAQ for the next steps.

Credential files and optional secret tooling

MCP configs need only the full binary path. The default credential file is ~/.secrets/.trello-mcp.secret on every platform (%USERPROFILE%\.secrets\.trello-mcp.secret on Windows). Locations and value rules follow avhn/secret, "Let coding agents use your credentials without reading them". The bare name trello-mcp resolves to this file: secret show trello-mcp lists masked names and secret exec -f trello-mcp ... can launch a configured consumer. Using secret is optional; trello-mcp reads files itself.

TRELLO_API_KEY=your-api-key
TRELLO_TOKEN=your-token
TRELLO_TOKEN_SCOPE=read,write

Values follow secret stash: unquoted KEY=VALUE, nonempty, no NUL, CR, embedded newlines, boundary whitespace or surrounding quote pairs; one final LF is allowed. Scope is optional (unknown, treated as writable); read forces read-only even with TRELLO_READ_ONLY=0.

Precedence: environment TRELLO_API_KEY + TRELLO_TOKEN > absolute TRELLO_MCP_CREDENTIALS file > dedicated default file > ~/.secrets.env. Partial environment pairs fail; missing or credential-free files fall through without merging keys across files. The final fallback is secret's shared top-level store; only the three Trello keys are interpreted and unrelated values are ignored, never logged. An unsafe shared file is bypassed when an earlier source exists, otherwise it produces a clear error. Auth never modifies the shared store.

Auth creates missing directories as 0700 and files as 0600 on Unix, or protected owner-only DACLs on Windows. Existing folder permissions are never changed. Symlinked files/parent paths, foreign ownership, group/world-writable Unix directories and group/world-accessible files are refused. Windows verifies owner and protected owner-only DACLs; the shared file's home parent need not have an owner-only DACL. See exact errors and corrective permission instructions.

auth, auth status and auth logout accept --file /absolute/path/account.secret. Set TRELLO_MCP_CREDENTIALS for future client processes; environment credentials still override files. Status validates the username and granted scope, one fact per line without secrets; shared fallback reports Credential source: file ~/.secrets.env (shared store). Logout removes only the three keys, preserves unrelated lines/comments and deletes the file only if empty. It does not revoke tokens or clear environment/shared credentials. Restart clients afterward.

Without the browser flow, privately edit the three lines with an existing key/token and actual scope. On Unix create a missing folder with mkdir -m 700 ~/.secrets, edit after umask 077, then chmod 600 ~/.secrets/.trello-mcp.secret. Never automatically chmod an existing shared folder. Alternatively secret stash trello-mcp TRELLO_API_KEY (and token/scope equivalents) prompts privately. Windows requires protected owner-only DACLs in Properties > Security. Run trello-mcp auth status to validate.

Troubleshooting: no credentials found means run auth and restart; permission refused means follow the exact storage error and safe fix; 401 means check token expiry/revocation and the matching key; wrong workspace denial means inspect server_health with {"detail":"policy"} and fix server policy rather than changing credentials.
