Installation and account setup

Install trello-mcp

Install a verified binary, connect your Trello account and let your MCP client launch the local stdio server.

These guides follow the current source tree, including trello-mcp auth. Release availability can differ. If your binary does not recognize auth, build the current source or use a complete environment credential pair as described in the credentials guide.

  • Windows

macOS and Linux

curl -fsSL https://raw.githubusercontent.com/avhn/trello-mcp/main/install.sh | sh

The POSIX installer downloads the latest release, verifies its SHA-256 checksum and installs to ~/.local/bin. Add that directory to your shell and MCP client's PATH, or use the full installed path.

  • Release binaries support Linux amd64/arm64 and macOS amd64/arm64.
  • Requires curl, tar and sha256sum or shasum.
  • Choose a version with TRELLO_MCP_VERSION or a destination with INSTALL_DIR. For a piped install, set them on sh, not curl.
  • If a release or platform asset is unavailable, it falls back to go install at @latest when Go is available, even if a release version was requested.

Example custom destination:

curl -fsSL https://raw.githubusercontent.com/avhn/trello-mcp/main/install.sh | INSTALL_DIR="$HOME/bin" sh

The POSIX installer also supports Windows amd64 through a shell such as Git Bash, using unzip rather than tar. For Windows ARM64, use the native PowerShell installer.

Windows PowerShell and cmd

In Windows PowerShell 5.1 or PowerShell 7:

irm https://raw.githubusercontent.com/avhn/trello-mcp/main/install.ps1 | iex

From cmd:

powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/avhn/trello-mcp/main/install.ps1 | iex"

The native installer downloads the latest Windows amd64 or ARM64 release and verifies SHA-256. No administrator privileges or Go installation are needed.

  • Default executable: %LOCALAPPDATA%\Programs\trello-mcp\trello-mcp.exe.
  • Adds the install directory to your user PATH, without duplicating an existing entry. It does not change the machine PATH. Open a new terminal afterward.
  • Set $env:TRELLO_MCP_VERSION to a release tag or $env:INSTALL_DIR to a destination before running the installer.
  • Unlike the POSIX installer, it fails if the release is unavailable rather than building from source.

Windows refuses local path uploads and attachment downloads because their ownership and path checks require Unix. Base64 uploads and URL attachments remain available when read-only mode is off.

Release archives and building from source

Prefer to inspect the installer first? Read the POSIX installer source or PowerShell installer source. You can also download platform archives and checksums.txt directly from GitHub releases.

Installing from source requires Go 1.26 or newer; the module selects the Go 1.27.1 toolchain:

go install github.com/avhn/trello-mcp/cmd/trello-mcp@latest

Go installs to GOBIN, or normally ~/go/bin, rather than ~/.local/bin.

To use current source behavior not yet included in your release, obtain a checkout from the source repository, then run these commands in its root:

go build -o trello-mcp ./cmd/trello-mcp
./trello-mcp --version
./trello-mcp auth

On Windows, build with go build -o trello-mcp.exe ./cmd/trello-mcp, then run .\trello-mcp.exe auth. Configure clients with the full path to the binary you built. A source build's default version string is not a release-feature guarantee.

Connect your Trello account

trello-mcp auth
  1. Run auth in a terminal, outside the MCP transport. Use the full executable path if needed.
  2. Create an API key manually at Trello Power-Ups administration when prompted.
  3. Choose the requested scope. Write access is the default: Enter at Allow write access? [Y/n] means yes.
  4. Open the printed authorization link if your browser does not open automatically, then approve access.
  5. Paste the token at the hidden terminal prompt. The authorization URL includes your API key, so keep that link private too.

The command validates your credentials and saves them in ~/.secrets/.trello-mcp.secret. Restart your MCP client afterward.

Read-only access and token lifetime

trello-mcp auth --read-only
trello-mcp auth --write --expiration 30days

These are alternatives, not sequential setup steps. --read-only requests a read-only token. --write skips the scope question. --expiration accepts 1day, 30days or never (the default).

Check status or remove saved credentials

trello-mcp auth status
trello-mcp auth logout

Status reports the source, username and granted scope without secrets. Logout removes only the three Trello keys, preserving unrelated lines and comments (deleting the file only if empty); it does not revoke the token at Trello or unset environment credentials. Restart the MCP client after connecting or logging out.

As an alternative, set both TRELLO_API_KEY and TRELLO_TOKEN in the server's environment. A complete pair overrides the saved file; a partial pair is an error. Never commit credentials or share them in chat. See the credential storage and permission rules.

Configure your MCP client

The installers only print setup instructions. They never ask for credentials or register an MCP server automatically. Your client launches the executable as a local stdio process; this is not a hosted HTTP endpoint.

Continue to the Claude, Codex, ChatGPT and OpenCode client setup guide. If the server initializes but only exposes server_health, connect your account in a terminal and restart the client.

Credential files and optional secret tooling

MCP configs need only the full binary path. The default credential file is ~/.secrets/.trello-mcp.secret on every platform (%USERPROFILE%\.secrets\.trello-mcp.secret on Windows). Locations and value rules follow avhn/secret, "Let coding agents use your credentials without reading them". The bare name trello-mcp resolves to this file: secret show trello-mcp lists masked names and secret exec -f trello-mcp ... can launch a configured consumer. Using secret is optional; trello-mcp reads files itself.

TRELLO_API_KEY=your-api-key
TRELLO_TOKEN=your-token
TRELLO_TOKEN_SCOPE=read,write

Values follow secret stash: unquoted KEY=VALUE, nonempty, no NUL, CR, embedded newlines, boundary whitespace or surrounding quote pairs; one final LF is allowed. Scope is optional (unknown, treated as writable); read forces read-only even with TRELLO_READ_ONLY=0.

Precedence: environment TRELLO_API_KEY + TRELLO_TOKEN > absolute TRELLO_MCP_CREDENTIALS file > dedicated default file > ~/.secrets.env. Partial environment pairs fail; missing or credential-free files fall through without merging keys across files. The final fallback is secret's shared top-level store; only the three Trello keys are interpreted and unrelated values are ignored, never logged. An unsafe shared file is bypassed when an earlier source exists, otherwise it produces a clear error. Auth never modifies the shared store.

Auth creates missing directories as 0700 and files as 0600 on Unix, or protected owner-only DACLs on Windows. Auth also repairs the default ~/.secrets to 0700 after refusing symlinks and foreign owners, matching secret stash. Reads and logout require no group/world bits (0077) there. Custom parents and the home parent of read-only ~/.secrets.env may be 0755, but not group/world writable (0022); custom modes are unchanged. Symlinked files/parent paths, foreign ownership, group/world-writable Unix directories and group/world-accessible files are refused. Windows verifies owner and protected owner-only DACLs; the shared file's home parent need not have an owner-only DACL. See exact errors and corrective permission instructions.

Save and logout hold the target parent's .write-lock across the entire read-modify-write, including deletion. This mkdir protocol matches secret stash for the default store, with private token/PID files and token-checked release. Reads do not lock. Writers retry every 100ms for up to 3s. Timeout errors name the lock: verify its PID is stopped before manually removing it. Locks are never auto-stolen. Logout rechecks content before deletion and rewrites a changed file instead. Writers ignoring the protocol cannot be serialized.

auth, auth status and auth logout accept --file /absolute/path/account.secret. Set TRELLO_MCP_CREDENTIALS for future client processes; environment credentials still override files. Status validates the username and granted scope, one fact per line without secrets; shared fallback reports Credential source: file ~/.secrets.env (shared store). Logout removes only the three keys, preserves unrelated lines/comments and deletes the file only if empty. It does not revoke tokens or clear environment/shared credentials. Restart clients afterward.

Without the browser flow, privately edit the three lines with an existing key/token and actual scope. On Unix create a missing folder with mkdir -m 700 ~/.secrets, edit after umask 077, then chmod 600 ~/.secrets/.trello-mcp.secret. Ensure an existing ~/.secrets belongs to you and is intended to be private, then run chmod 700 ~/.secrets; auth and secret stash also repair this default. Alternatively secret stash trello-mcp TRELLO_API_KEY (and token/scope equivalents) prompts privately. Windows requires protected owner-only DACLs in Properties > Security. Run trello-mcp auth status to validate.

Troubleshooting: no credentials found means run auth and restart; permission refused means follow the exact storage error and safe fix; 401 means check token expiry/revocation and the matching key; wrong workspace denial means inspect server_health with {"detail":"policy"} and fix server policy rather than changing credentials.
